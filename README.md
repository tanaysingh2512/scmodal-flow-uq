# scMODAL + Conditional Flow Matching: Calibrated Uncertainty for Cross-Modal Protein Imputation

Extends [scMODAL](https://github.com/gefeiwang/scMODAL), a multimodal
single-cell integration framework, with conditional flow matching for
calibrated uncertainty quantification in cross-modal protein imputation
(predicting protein abundance from RNA, and vice versa).

**A note on what this repository is:** the numbers below are *historical
results*, produced by the original research notebook
(`notebooks/scMODAL_FINAL_AllPhases_StretchGoals.ipynb`) and recorded in
`docs/decisions.md`. The `src/`/`scripts/` code is a migration of that
notebook into a runnable pipeline, audited line-by-line against it for
fidelity (see `docs/decisions.md` for the full audit trail) — but it has
not been re-executed end-to-end since the split, because doing so requires
raw data and trained checkpoints that are not included in this repo (see
"Data" below). Treat the code as a faithful, reviewed reproduction of the
original pipeline, not as independently re-verified against a fresh run.

## Headline result (historical, from the original notebook)

- scMODAL's deterministic decoder gives accurate point predictions.
- A conditional flow matching model gives comparable (not equal — about 1
  correlation point lower on both PBMC CITE-seq and TEA-seq datasets)
  accuracy, in exchange for calibrated, informative per-cell uncertainty
  that flags biologically hard cases.
- totalVI reports a higher raw correlation (0.664) than the original
  scMODAL checkpoint's deterministic decoder (0.485) or flow (0.475) — the
  notebook's own stated comparison — but **this is not a validated
  apples-to-apples number**, for two independent reasons: (1) totalVI and
  scMODAL/flow are evaluated in different feature spaces (totalVI: 228 raw
  ADT protein counts; scMODAL/flow: 260 log1p-normalized, z-scored feature
  slots representing those same 228 proteins, since the correspondence
  table maps some proteins to multiple genes), with no existing procedure
  in this project to reconcile them; and (2) the reproducibility-fixed
  retrain (`model_v2`, 0.520 deterministic) was never actually compared
  against totalVI at all — that comparison happened before `model_v2`
  existed. See `docs/decisions.md` for the exact dimensional breakdown.
  **Do not treat "totalVI wins on accuracy" as a settled finding, and do
  not cite 0.520 in the same breath as totalVI's 0.664 — they were never
  compared.** (Calibration coverage, by contrast, is a dimensionless
  percentage and *is* directly comparable: totalVI is consistently
  underconfident, the opposite failure mode from the flow's overconfidence.)
- A simple post-hoc scalar correction closes most of the flow's calibration
  gap, on both datasets, even though the fitted scale factor itself differs
  by more than 4x between them (0.520 vs. 0.120) — the *method* generalizes,
  the *scale factor* does not.
- A follow-up experiment (down-weighting uncertain cross-modal anchor links
  during fine-tuning) is a well-validated **null result**: no overall
  accuracy gain, and a small but real regression on the highest-uncertainty
  cells, confirmed via a 5-seed sweep, a 4-point strength sweep, and an
  uncertainty-signal swap.

See `docs/flow.md` for the exact pipeline order and `docs/decisions.md` for
why each piece of code ended up the way it did.

## Data

Raw CITE-seq PBMC and TEA-seq PBMC source files (`.h5ad`, count matrices)
are **not included in this repo** — they're large, and not this project's
to redistribute. `docs/flow.md` documents the exact expected paths and
layout; you need to source and place these yourself before `scripts/`
can run from scratch. Two small, non-sensitive reference tables *are*
committed as reproducibility fixtures (see `.gitignore` for the exact
negation rules): `CITE-seq_PBMC_v2/rna_protein_correspondence.csv` and
`data/tea-seq/protein_gene_conversion_new.csv`.

**TEA-seq path assumption, not yet independently verified:** the migrated
code assumes several TEA-seq companion files (`adt_scaled_gt.npy`,
`rna_scaled.npy`, the checkpoint) live one directory level deeper than
their top-level folder name suggests (`TEA-seq_PBMC/TEA-seq_PBMC/...`).
This was resolved from notebook evidence (see `docs/decisions.md`), not
from inspecting an actual filesystem — confirm it matches your real
`TEA-seq_PBMC/` directory before relying on `scripts/load_raw_data.py
--dataset teaseq --resume`.

## scMODAL dependency

scMODAL itself is tracked as a git submodule, not vendored — it's imported
via current-directory resolution (see `docs/decisions.md`), never
`pip install`ed.

**One-time setup for this repo** (done once, as part of the initial commit
sequence — see the maintainer's own setup notes if you're reading this
before that's happened):

```
git submodule add https://github.com/gefeiwang/scMODAL scMODAL
```

**For anyone cloning this repo afterward** (once the line above has already
been run and committed, so `.gitmodules` exists in the repo):

```
git clone --recurse-submodules <this-repo-url>
# or, if already cloned without that flag:
git submodule update --init
```

`git submodule update --init` only works once `.gitmodules` already exists
in the repository — it will not create the submodule reference for you on
a repo that doesn't have one yet.

## Environments

Two separate conda environments — do not merge them (see `docs/flow.md`):

```
conda env create -f environment-scmodal.yml   # everything except totalVI
conda env create -f environment-totalvi.yml   # totalVI baseline only
```

**Both `.yml` files are starting-point specifications, not verified `conda
env export` output.** Only a few packages carry pinned versions (taken
from project notes); most don't, because exact versions were never
confirmed against the real working environments. Regenerate the real files
with `conda env export --no-builds` from the actual environments before
treating these as guaranteeing reproducible installs.
